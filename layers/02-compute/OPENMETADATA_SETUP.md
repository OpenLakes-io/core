# OpenMetadata + Spark Integration Setup

## Overview

This guide covers the one-time setup required to enable automated lineage capture from Spark to OpenMetadata.

## Prerequisites

- **Layer 07 (Catalog) deployed** - This automatically creates the `openlakesbot` and stores its JWT token
- The token is generated by `layers/07-catalog/templates/bot-and-connector-setup-job.yaml`
- The `openmetadata-bot-token` secret should exist in the `openlakes` namespace

## One-Time Secret Creation

The `openlakesbot` JWT token has **unlimited expiry** and never needs renewal. You only need to create the secret once.

### Step 1: Verify Bot Token Exists

The bot token is automatically generated when you deploy Layer 07 (Catalog). The `bot-and-connector-setup-job` creates the `openlakesbot` and stores its unlimited-expiry JWT token.

```bash
# Verify the token secret exists
kubectl get secret openmetadata-bot-token -n openlakes
```

Expected output:
```
NAME                     TYPE     DATA   AGE
openmetadata-bot-token   Opaque   1      11h
```

**Note**: If this secret doesn't exist, redeploy Layer 07:
```bash
helm upgrade catalog ./layers/07-catalog -n openlakes --install
```

### Step 2: Create Spark OpenMetadata Secret

This copies the bot token into a secret accessible by Spark pods:

```bash
kubectl get secret openmetadata-bot-token -n openlakes \
  -o jsonpath='{.data.token}' | base64 -d > /tmp/bot-token.txt

kubectl create secret generic compute-spark-openmetadata \
  --from-file=jwt-token=/tmp/bot-token.txt \
  --namespace=openlakes

rm /tmp/bot-token.txt
```

### Step 3: Verify Secret Creation

```bash
# Check secret exists
kubectl get secret compute-spark-openmetadata -n openlakes

# Verify token content (should be ~651 characters)
kubectl get secret compute-spark-openmetadata -n openlakes \
  -o jsonpath='{.data.jwt-token}' | base64 -d | wc -c
```

Expected output: `651`

### Step 4: Deploy Layer 02 (Compute)

```bash
helm upgrade 02-compute ./layers/02-compute -n openlakes --install
```

The Spark master and worker pods will automatically:
- Load the OpenMetadata agent JAR (`/opt/spark/jars/openmetadata-spark-agent-1.0-beta.jar`)
- Inject the JWT token via `SPARK_OPENMETADATA_JWT_TOKEN` environment variable
- Configure lineage capture to `http://catalog-openmetadata-server:8585`

## Verification

### Check Spark Pods

```bash
kubectl get pods -n openlakes | grep spark
```

Expected:
```
compute-spark-master-*    1/1   Running
compute-spark-worker-0    1/1   Running
```

### Verify Configuration

```bash
# Get master pod name
MASTER_POD=$(kubectl get pods -n openlakes -l component=master -o name | grep spark)

# Check JAR exists
kubectl exec -n openlakes $MASTER_POD -- \
  ls -lh /opt/spark/jars/openmetadata-spark-agent-1.0-beta.jar

# Verify token injection
kubectl exec -n openlakes $MASTER_POD -- env | grep SPARK_OPENMETADATA_JWT_TOKEN

# Check configuration
kubectl exec -n openlakes $MASTER_POD -- \
  cat /opt/spark/conf/spark-defaults.conf | grep -A10 "OpenMetadata"
```

## Why No Token Sync Job?

Unlike typical JWT tokens, the `openlakesbot` token is configured with:
- **Unlimited expiry** (`"exp": null`)
- **Bot-type authentication** (no password rotation)
- **Admin role** (persistent permissions)

This means:
- ✅ **One-time setup** - Create secret once, never update
- ✅ **No sync overhead** - No periodic jobs or automation needed
- ✅ **Simplified deployment** - Fewer moving parts, less complexity
- ✅ **Reduced failure points** - No job failures or RBAC issues

## Troubleshooting

### Secret Missing After Deployment

If you deployed Layer 02 before creating the secret, pods will fail to start:

```bash
# Check pod status
kubectl get pods -n openlakes | grep spark

# If pods show ImagePullBackOff or CrashLoopBackOff, check events
kubectl describe pod -n openlakes <spark-master-pod> | grep -A5 Events
```

**Solution**: Create the secret (Step 2 above) and restart pods:

```bash
kubectl rollout restart deployment/compute-spark-master -n openlakes
kubectl rollout restart statefulset/compute-spark-worker -n openlakes
```

### Token Not Injected

If `SPARK_OPENMETADATA_JWT_TOKEN` is empty:

```bash
# Check if secret exists
kubectl get secret compute-spark-openmetadata -n openlakes

# Check secret content
kubectl get secret compute-spark-openmetadata -n openlakes -o yaml
```

**Solution**: Recreate the secret following Step 2.

### Lineage Not Appearing in OpenMetadata

1. **Verify Spark service registered**:
   ```bash
   kubectl logs -n openlakes catalog-openmetadata-bot-and-connector-setup \
     | grep -A5 "Spark"
   ```

2. **Check OpenMetadata logs**:
   ```bash
   kubectl logs -n openlakes <openmetadata-pod> | grep -i lineage
   ```

3. **Verify network connectivity**:
   ```bash
   kubectl exec -n openlakes <spark-master-pod> -- \
     curl -v http://catalog-openmetadata-server:8585/api/v1/health-check
   ```

## Updating the Secret (Only if Needed)

If you ever need to regenerate the bot token (rare), update the secret:

```bash
# Get new token
kubectl get secret openmetadata-bot-token -n openlakes \
  -o jsonpath='{.data.token}' | base64 -d > /tmp/new-token.txt

# Update existing secret
kubectl create secret generic compute-spark-openmetadata \
  --from-file=jwt-token=/tmp/new-token.txt \
  --namespace=openlakes \
  --dry-run=client -o yaml | kubectl apply -f -

rm /tmp/new-token.txt

# Restart Spark pods to pick up new token
kubectl rollout restart deployment/compute-spark-master -n openlakes
kubectl rollout restart statefulset/compute-spark-worker -n openlakes
```
